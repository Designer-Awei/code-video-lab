# 《刹车踏板进化史》制作复盘

## 发起：参考不是一张风格图，而是一整套生产方式

Awei 最初在 Cursor 中用 Opus5.5 启动工程。输入包括 @xilo2991 的 [长文教程](https://x.com/xilo2991/status/2104912748794589515)、@prasenx 的 [电影感视频参考](https://x.com/prasenx/status/2103851939457093635) 和对应提示词。参考提示词强调电影感、情绪与音乐节奏、通过代码生成每一帧、通过代码合成音乐，再交付 MP4。

实际选题是汽车刹车踏板的发展史，以当时的尊界 V800 测试事件引入，时长不超过十分钟。不是照搬参考的两分钟电子游戏主题，而是迁移其制作方法。

最初建立 `source → script → brief → storyboard → timeline → scenes → QA → render` 的工程链路。资料不是散落在聊天里，视觉也不是孤立的好看片段：每个判断有依据，每个镜头有叙事任务，每个文件有下一步的消费者。

## Opus5.5：框架、美术与前两章

按 Awei 的回溯，第一、第二章基本由 Opus5.5 完成，后面章节的骨架也先由它建立。作者尤其认可其分镜、物体建模与整体美术风格。

第一章将真实报道与程序化踏板总成放在一条叙事线上。踏板不是矩形图标：支架、轴、臂、踏面、推杆和脚坑共同定义它；模型需要完整装配才能可信地演出“踩下、回弹、断开”。报道保留真实截图与出处，示意动画承担结构解释。

第二章把历史机械与铜版画语言连接起来：奔驰专利车、车轮、杠杆和制动关系有具体模型；墨线、交叉排线和镜头运动使它有时代感。学习重点不是“有 Three.js”，而是如何把主题、结构、材质、后期和镜头合成一个识别度明确的画面。

作者后来提供 [mg-styles-15](https://github.com/Vincentwei1021/mg-styles-15)。它帮助把“精美一点”转为可以执行的风格技法、弹簧参数、设计和动作评审。早期分镜保存在 [archive/storyboard-v1.md](archive/storyboard-v1.md) 与 [archive/storyboard-v2.md](archive/storyboard-v2.md)，它们记录方向变化，不是当前执行规范。

## Grok4.7：接手骨架与后续章节

按作者说明，后续章节在 Opus 建好骨架后由 Grok4.7 接手。过程中大量实际审片意见推动成片成熟：字体与模型遮挡、模型连接、踏板穿模、车轮辐条、机位方向、边界溢出、画面留白和配色都被反复修正。

这说明“搭好所有章节”不等于完成。粗略块体必须变成能说明问题的机械结构；世界坐标中分开的物体，在最终相机下仍可能挡住文字。评审应看最终投影，而不是只看建模参数。

第三章之后统一为第四章的金色放射背景，文字衬底逐步去掉。第六章增加彩色模型、纤维与强度解释、碰撞时踏板让位的结构示意；第七章调整踏板朝向、位置、踩下回弹及文字安全区。删掉看不清或不必要的连接线，也是一种设计决策。

## GPT-6.1：第八章、声音替换与工程化

GPT-6.1 接手后主要完善收尾：把“杠杆、木块、钢板、复合材料、传感器”拆成真正不同的机械插画，而不是重复车与踏板模型的机位。右侧历史轮播也改为完整的三踏板、液压剖面、盘式、ABS、线控和 EMB 组件。

第八章开头采用贯穿画面高度的连续胶片，齿孔、片格与部件共享位移；轻微曝光闪烁由时间和固定哈希求值。结尾独立呈现“我是Awei”，快速逐字回删，再输入“我们下期见”：暖朱红宋体、印刷厚度、逐字弹簧和随字移动的光标，最后整帧淡黑。

口播先使用 Awei 原声，后按作者要求换成 Voicebox 的“雷布斯”音色。换声并非把新 WAV 从零秒贴进去：原停顿、章节时长和成片额外的两秒封面都必须保持。做法是以原录音的声学特征为节奏参照，在双方静音区剪接，段内用保持音高的时间伸缩，对长停顿保留新录音的轻微呼吸与底噪。没有使用 Whisper 转录；这也不构成逐字正确性证明。

## 从审片中提炼出的可迁移经验

- **前五秒先解决注意力。** 最初踏板先出现、配音数秒后才开始，被改为报道先行，再进入完整动画。素材与画面漂亮并不能代替开场叙事。
- **主体的外形必须对应名词。** “一块木头”不能用另一辆车代替，“一个传感器”也不能只是同一踏板转个角度。
- **用最终画面检查连接关系。** 轴、轮毂、辐条和连杆要有共同的参照；踏板围绕真实支点动作，脚坑与踏面不能穿模。
- **以屏幕区域分工。** 文字、机械主体与旁注各有安全区；模型最极端姿态、爆炸图和碎片也要检查，不只看静止初帧。
- **过渡是一套关系。** 胶片齿孔不能走自己的路；轮播画面和左侧文案不能同时糊在一个位置；光标必须真正跟着字符增删。
- **让声音成为时间轴。** 保留自然停顿，不把每句话都裁成急促的一口气；替换音色时优先保护已审核的镜头节奏。
- **把评审变成材料。** 检查代表帧、动作极值和转场中间帧；将错误、修改和约束留在文档，下一位模型无需重新踩坑。

## 如何读这份案例

先看 [八章画面](gallery/overview.jpg)，再读 `brief.md`、当前 `storyboard.md`、`timeline.json`。随后精读第一、第二章和它们调用的模型。不要把代码名字换成新主题就宣称完成迁移；新的题材需要新的资料、名词对应的资产、视觉母题和镜头目标。

这里的分工记录来自作者对协作过程的回溯，没有完整的逐轮 Git 历史，因此不把某个文件的所有行武断归属于一个模型。作品的最终判断来自 Awei 持续审片与决策；模型能力是在这一协作过程中发挥出来的。
